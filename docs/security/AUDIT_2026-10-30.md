# Raport audytu bezpieczeństwa — 2026-10-30

## Zakres

Audyt obejmował:

- repozytorium BetterDesk na gałęzi `dev`;
- publiczne repozytorium [BetterDesk-Client](https://github.com/UNITRONIX/BetterDesk-Client), checkout `master`;
- alerty Dependabot, lockfile npm/Go/Rust, kod panelu, API, WebSocket, aktualizator, obrazy Docker i build klienta;
- testy jednostkowe/security oraz kontrolowany pentest lokalnego obrazu Docker.

Nie testowano produkcyjnego hosta, prawdziwych urządzeń ani zewnętrznej sieci. Nie wykonywano destrukcji danych, eksfiltracji ani rzeczywistego RCE.

## Stan wyjściowy GitHub

API GitHub potwierdziło 14 otwartych alertów Dependabot:

- rootowy, nieużywany Vitest: krytyczne `tinypool`, podatności Vitest/Vite/source-map;
- `qs` w `web-nodejs`: runtime, poprawione od `6.16.1`;
- `js-yaml` w toolchainie Jest: poprawione od `3.15.2`;
- `deepmerge` w Jest: alert dev-only, brak poprawionej wersji upstream;
- kilka alertów Vite/launch-editor, dotyczących lokalnego dev-servera Windows.

## Wdrożone poprawki

1. Usunięto nieużywany rootowy `vitest` i odświeżono `package-lock.json`. Rootowy `npm audit` raportuje 0 podatności.
2. Podniesiono override’y `qs` i `js-yaml` w konsoli. Produkcyjny `npm audit --omit=dev` raportuje 0 podatności. `deepmerge` pozostaje jawnie odnotowany jako dev-only bez poprawki upstream; wymuszenie downgrade’u Jest byłoby niebezpieczną zmianą łamiącą.
3. Dodano wspólną kontrolę zakresu urządzenia przed proxy agentów. Obejmuje również cache/offline telemetry i operacje zdalne.
4. Pobieranie hasła z org vault wymaga teraz `device.connect` w panelu i Go API; `viewer` nie ma dostępu.
5. `/ws/relay` wymaga `device.connect` dla sesji panelowych, tak jak `/ws/rendezvous`; guest access pozostaje osobną ścieżką.
6. Redirecty aktualizatora są ograniczone do HTTPS i hostów `api.github.com` / `raw.githubusercontent.com`, z limitem trzech redirectów.
7. Zaktualizowano Go toolchain do `go1.26.10` i `golang.org/x/crypto` do `v0.55.0`. Zaktualizowano obrazy Go w `Dockerfile` i `Dockerfile.server`.
8. Dodano rootowy workflow audytu npm oraz usunięto z konfiguracji Dependabot ścieżki do nieobecnych podprojektów.
9. W Dockerfile klienta usunięto `--no-check-certificate`, przypięto i zweryfikowano checksumami CMake, Sciter SDK i rustup-init oraz usunięto niepotrzebne `sudo NOPASSWD:ALL`.
10. Z produkcyjnych obrazów BetterDesk usunięto bundlowane npm/npx, ponieważ runtime nie korzysta z npm; ogranicza to powierzchnię podatnego `tar`.

## Potwierdzone problemy kodu

### Wysokie — IDOR zakresu urządzeń

Przed poprawką endpointy proxy agentów sprawdzały tylko `device.view`/`device.edit`, ale nie `deviceGroupService.userCanAccessDevice`. Użytkownik z uprawnieniem, znanym identyfikatorem urządzenia i ograniczonym zakresem mógł odczytać telemetry, clipboard, screenshot lub użyć operacji zdalnych poza zakresem.

Poprawka: wspólny guard w `web-nodejs/routes/devices.routes.js`.

### Średnie — hasło vault dla `viewer`

Przed poprawką `GET /api/devices/:id/connect-password` wymagał `device.view`, a rola `viewer` posiada tę permission. Poprawka wymaga `device.connect` po stronie Node i Go.

### Średnie — luka RBAC w `/ws/relay`

Przed poprawką sesja panelowa bez `device.connect` mogła przejść przez `/ws/relay`, podczas gdy `/ws/rendezvous` była blokowana. Poprawka ujednolica kontrolę permission.

### Niskie — redirecty aktualizatora

Aktualizator podążał za `Location` bez sprawdzania hosta. Nie był to bezpośredni SSRF bez kompromitacji odpowiedzi GitHub, ale osłabiał defense-in-depth. Dodano walidację hosta, HTTPS i limit redirectów.
